## Install and bootstrap

1. Clone `https://github.com/vtmedia0910/TaXuaLand`, use Node 24 and pnpm 11.19.0, then `pnpm install --frozen-lockfile`. CI repeats this from a clean checkout. The lockfile pins dependencies. Python GIS tooling is a separate environment from `pipelines/requirements.txt`.
2. Provision LAND-only PostgreSQL 17 with PostGIS. Local option: set a new `DATABASE_OWNER_PASSWORD` in a private process environment and run `docker compose -f infra/compose.yml up -d`. Local service binds 127.0.0.1:55432. Never connect to BIKER/TRIP or reuse their secrets.
3. Use the owner connection in a private operator environment file (`DATABASE_URL`) to run `node --env-file=<operator-env> infra/migrate.ts`. The database must be new LAND or an existing LAND installation. Migrations are ordered/checksummed; never edit an applied SQL file. Keep private environment files outside version control.
4. Supply a new 32+ character `DATABASE_APP_PASSWORD` to `node --env-file=<operator-env> infra/provision-runtime.ts`. This creates `land_app` with limited grants; it deliberately does not overwrite an existing role. Bootstrap an account using `infra/bootstrap-admin.ts` with `SERVER_BOOTSTRAP_EMAIL`, a 14+ character `SERVER_BOOTSTRAP_PASSWORD` and `SERVER_BOOTSTRAP_ROLE=SYSTEM_ADMIN` in the operator environment. Remove bootstrap secrets from the runtime environment afterward. No default credentials exist.
5. Put the limited `DATABASE_URL` and exact `SERVER_ORIGIN` in `apps/web/.env.local` for local execution, or inject them from the runtime secret manager. HTTPS is required except loopback QA; login/write Origin must match. Set absolute `LAND_WORKSPACE_ROOT`; the repository location is the local default. LOCAL keeps `<root>/work/object-store/private` private and durable. STAGING/PRODUCTION configure S3 per [object storage](object-storage.md), with no persistent application volume. Parser sources/dependencies must be readable and the OS temporary directory writable. Migrate legacy `work/imports` inspections before removing the old volume. Repo-root `.env.local` can hold the separate owner/test connection; never copy it into the web runtime image/static hosting.
6. Configure an AOI with documented source/version. `infra/configure-aoi.mjs` installs only the explicitly labeled demo coverage if none exists. Do not treat it as an official Tà Xùa boundary. Register sources and process DEM/roads using [pipeline instructions](../../pipelines/README.md). The local adapter verifies/publishes sample assets under ignored `apps/web/public/spatial`; these binaries are intentionally absent from Git.
7. Run `pnpm check`. For local integration tests set repo-root `DATABASE_TEST_URL` to a dedicated local maintenance connection with CREATEDB; it creates/drops only unique test databases. Without this variable the PostGIS suites skip, so that run alone is insufficient acceptance evidence. GitHub CI supplies its own PostGIS service.
8. Run `pnpm --filter @land/web start`. The wrapper validates environment, database identity, role privileges and parser/private-volume access before serving. Use `--hostname 127.0.0.1 --port 3000` when starting behind a local reverse proxy. `/map` and `/admin/login` must respond; inspect `/admin/diagnostics` and run the documented production E2E fixture suite in an isolated QA environment. Use the wrapper, not bare `next start`, in deployment.

`DATABASE_*`/bootstrap values are private; only the required limited DATABASE_URL reaches the server runtime. No `NEXT_PUBLIC_*` secret variable is used. Terrain/road URLs and checksums come from approved release DTOs; workbook cells cannot configure them. `STORAGE_PRIVATE_ROOT`/`CESIUM_TERRAIN_URL` are not active runtime settings in this adapter and are deliberately absent from `.env.example`.

## Production infrastructure

Run under a dedicated unprivileged OS account/container with a read-only application filesystem and separate ephemeral scratch. Only LOCAL needs durable private filesystem objects. Parser child receives no app secrets and Node permissions restrict its capabilities; also restrict parser egress and apply OS resource limits. Set ingress upload/time/concurrency and login/IP rate limits at a trusted reverse proxy; do not trust spoofed forwarding headers. Enable HTTPS, secret rotation, restricted logs, alerting and backups. Keep raw workbook/GIS zones private and separate from public bucket/CDN credentials.

Promote spatial assets by uploading a complete new version, checking hashes, recording source/CRS/vertical datum/QA/pipeline provenance, then atomically switching the database release pointer. Raw/normalized/derived assets stay private. Never overwrite published object bytes; use one-year immutable caching only on versioned URLs. The local adapter is sufficient for Phase 0 QA; production durable bucket upload/CDN integration is an operator/infrastructure setup step before public launch. Provider credentials stay in a secret manager, never editable registry fields.

Schedule `node --experimental-transform-types --env-file=<operator-env> infra/expire-import-files.mjs` daily with LAND-only operator credentials and private storage configuration. It removes expired raw/inspection objects and obsolete legacy files after seven days while retaining audit/staging/provenance; see [migration and retention](object-storage.md#migration-retention-and-recovery). Back up PostgreSQL and asset manifests/objects together. On local QA, `node --env-file=<operator-env> infra/verify-backup.mjs <postgres-bin-directory>` dumps to ignored `work/backups`, restores into a unique `land_restore_<uuid>`, verifies counts/product/spatial integrity and drops only that temporary database. Dumps contain private data/hashes; retain encrypted with restricted access and never commit. Restore rehearsal omits roles/grants, which must be provisioned independently from reviewed scripts. A local restore rehearsal passed on 2026-09-08.

For rollback, preserve audit and immutable versions. Revert application code to a compatible release; do not reverse a data migration blindly. Restore a backup into a new isolated LAND database, validate it and then switch runtime connection under an operator-controlled maintenance window. Retire bad asset releases and publish a reviewed replacement. Rights revocation may require CDN removal/invalidation in addition to registry/source kill switches.
