## IMAGERY ENABLEMENT

- Source: proposed canonical name `Copernicus Sentinel-2 Collection 1 Level-2A Surface Reflectance / AWS Open Data COGs`; `providerId=null` because AWS/Earth Search is acquisition-only, not a browser/runtime provider; `category=IMAGERY`; `authorityLevel=THIRD_PARTY` because LAND consumes Element 84/AWS COG derivatives of Copernicus products; `freshnessClass=VOLATILE`; source CRS is set only after the selected Item's `proj:code` is confirmed (expected, not asserted, `EPSG:32648` for this AOI). Keep `status=REVIEW_REQUIRED` until rights and exact source evidence are owner-accepted.
- legal/licence evidence: proposed `licenseName=Copernicus Sentinel Data Legal Notice (rev. 1)` and `licenseReference=https://cds.climate.copernicus.eu/licences/ec-sentinel`. The notice supports the proposed rights mapping `commercialUse/publicDisplay/caching/derivatives/redistribution=ALLOWED`, subject to explicit owner acceptance; `legalReviewedAt=null` unless an actual external legal review occurs. A cropped/reprojected/tiled LAND product must display `Contains modified Copernicus Sentinel data [acquisition year]`. Also retain the AWS acquisition citation and access date. See [the primary-source evidence note](../data-sources/sentinel-2-l2a-aws-cog-evidence.md).
- acquisition source: discover via Earth Search v1 collection `sentinel-2-c1-l2a`, backed by AWS Open Data bucket `e84-earth-search-sentinel-data` in `us-west-2`. Earth Search/STAC and AWS asset URLs are evidence/acquisition inputs only. They must never be emitted as runtime tile endpoints or accepted from browser input.
- candidate-selection policy:
  1. Use the owner-approved active PostGIS AOI `TX-AOI-2026-001` (`1a169926-5c2c-48a7-a880-8e62b2b1d33d`) and pin its exact GeoJSON/SHA-256. The active PostGIS row must match this identity and geometry.
  2. Use a bounded owner-approved UTC acquisition interval. Proposed discovery default: the rolling 24 months ending at query time.
  3. Discovery filter: Item geometry intersects the AOI and scene `eo:cloud_cover <= 20%`.
  4. Acceptance, independently of discovery: selected Item valid-data footprint (or union of the minimum compatible Items) must satisfy `ST_Covers(valid_footprint, AOI)`; bbox/nominal MGRS coverage is insufficient; AOI nodata/saturated pixels must be 0%.
  5. AOI obstruction gate: SCL classes 3, 8, 9, and 10 (cloud shadow, medium/high cloud, cirrus), plus class 11 when the product goal requires snow-free ground, must occupy no more than 10% of AOI pixels. Record each class separately. Classes 0 and 1 fail valid coverage rather than being counted as cloud.
  6. Rank passing candidates by newest sensing timestamp, then lower AOI obstruction, then stable Item ID. Acquisition/sensing time is freshness; generation, LAND processing, delivery, and publication times remain separate.
  7. Prefer one Item. Mosaic only the minimum Items from the same sensing acquisition/orbit and compatible processing baseline. Reject cross-date or color-balanced composites in Slice 1C.
  8. The proposed 24-month/20%/10%/SCL policy is exact enough to run but still needs owner acceptance before acquisition or publication.
- acquisition evidence: preserve the exact STAC API/collection/query geometry/date range/query time and returned Item JSON; Item/collection/self/source links; Item ID; complete Sentinel product name/URI; platform/instrument; sensing time; generation time; processing baseline; relative orbit; MGRS tile/grid; WGS84 geometry/bbox; scene cloud; and every selected asset's key/URL/roles/MIME/GSD/byte size/projection/shape/transform/upstream `file:checksum`. Preserve upstream Multihash and compute LAND SHA-256 for every fetched evidence/asset byte; never substitute S3 ETag for a content checksum.
- expected resolution: display input is the Item `visual`/TCI COG at nominal 10 m GSD; SCL QA input is nominal 20 m. `dataset_releases.resolution=10` metres only after asset metadata and output sampling confirm it. Ten-metre GSD is not ten-metre positional accuracy and does not establish verification.
- CRS/target CRS: retain the exact native asset `proj:code` as `source_crs`; PostGIS coverage geometry and public bbox remain EPSG:4326 longitude/latitude. The derived tile pyramid is explicit `EPSG:3857` Web Mercator XYZ for Cesium's native URL-template provider. This is a delivery representation under the accepted explicit-CRS policy, not a change to PostGIS geometry authority.
- Dataset: code `TX_IMAGERY_BASE`; name `Tà Xùa Sentinel-2 L2A true-colour imagery`; kind `IMAGERY`; linked to the accepted Source. It persists across immutable acquisitions.
- proposed Release contract: version pattern `TX-IMAGERY-S2L2A-YYYYMMDDTHHMMSSZ-001`; `source_version` is SHA-256 of canonical source-lock JSON containing the selected Item and asset identities/checksums; `pipeline_version=land-imagery-1.0.0`; exact source CRS; `target_crs=EPSG:3857`; vertical datum `UNKNOWN`; bbox is the exact EPSG:4326 AOI; resolution 10 m; licence name as above; Release checksum is the published manifest SHA-256; registration stops at `APPROVED`.
- raw/normalized/derived/published contract:
  - `raw` private: canonical STAC Item JSON, source-lock JSON, selected `visual`/TCI and `scl` asset evidence/bytes or an explicitly recorded COG range-acquisition record, plus product/tile metadata. Each descriptor has MIME, size, upstream Multihash when available, and LAND SHA-256; no public URL.
  - `normalized` private: AOI-clipped, valid-mask-checked true-colour GeoTIFF and AOI SCL/quality raster with explicit CRS/geotransform/nodata, no public URL.
  - `derived` private: deterministic EPSG:3857 mosaic/warp and QA report; no public URL.
  - `published`: strict manifest plus only release-scoped 256×256 PNG XYZ tiles. No source COG/STAC/vendor URL is public runtime configuration.
- processing pipeline: validate source locks before reading; window-read/copy the bounded AOI; use the source TCI without invented pixels or sharpening; calculate valid/cloud class metrics from SCL; reject policy failures; clip to the authoritative AOI; if a same-acquisition mosaic is unavoidable, use masks and stable Item-ID ordering with no feathering/color balancing; reproject once to EPSG:3857 with bilinear RGB resampling and nearest-neighbour masks; create lossless alpha PNG tiles; record GDAL/Rasterio/PROJ/libpng versions and exact options; validate output coverage, decode, tile bounds, object limits, and hashes. Maximum zoom 14 for confirmed 10 m input; resampling does not create extra detail. If the bounded release exceeds 5,462 objects, 128 MiB total, or 32 MiB per object, stop for review rather than raising limits silently.
- manifest: strict `LAND_IMAGERY_V1` JSON, maximum 1 MiB, canonical serialization, containing schema/version/Dataset code, source-lock hash, selected Item/product IDs, sensing/generation/processing timestamps, source/processing versions, source/target CRS, 4326 bbox, source/output resolution, 256 tile size, `WEB_MERCATOR_XYZ`, levels 0–14, relative `tileUrlTemplate={z}/{x}/{y}.png`, per-tile `{bytes,sha256}`, cloud/SCL metrics and thresholds, licence reference, exact modified-Copernicus attribution, AWS access citation/date, `verificationStatus=UNKNOWN`, and limitations including no positional-accuracy claim. No arbitrary absolute tile URL is permitted in the manifest.
- tile hashes: SHA-256 every generated PNG; require an exact one-to-one match between manifest tile entries, registered `dataset_assets`, local published files, and R2 objects. The manifest SHA-256 becomes the Release checksum. Registration, delivery, and provider acceptance independently verify bytes; Cesium consumes only the release-scoped server-derived template.
- delivery: extend the existing operator-only delivery path narrowly for `IMAGERY`. Canonical keys are `spatial/imagery/{dataset-uuid}/{release-uuid}/manifest.json` and `.../{z}/{x}/{y}.png`; manifest MIME `application/vnd.land.imagery+json`, tiles `image/png`; create-only immutable PUT, complete readback, exact-origin receipt/audit, anonymous GET/HEAD, exact-origin CORS, one-year immutable cache. A partial upload creates no receipt and no public projection.
- receipt: reuse immutable `spatial_object_deliveries`; no new receipt model. The receipt proves delivery/readback to one configured origin, not publication, source authority, availability forever, or verification.
- publication: extend `publishRelease()` to admit `IMAGERY` only when Source rights/status/provider pass, Release is `APPROVED`, bbox equals/covers the active AOI, source CRS is explicit, target CRS is `EPSG:3857`, resolution is 10 m, published manifest checksum matches the Release checksum, every registered tile matches the strict manifest, the completed pipeline contains approved QA evidence, and the exact-origin receipt exists. Publication remains an explicit authenticated operation and retires the prior published imagery Release.
- publicLayers imagery projection: extend the existing typed server projection with nullable `imageryManifestUrl`, `imageryRelease`, `imageryChecksum`, and a strict public-safe metadata object containing Source name, licence/reference, attribution, sensing timestamp, coverage, source/output resolution, and `verificationStatus=UNKNOWN`. Resolve the manifest URL only from configured origin + Release/Dataset IDs + delivery receipt. Never expose source asset URLs, STAC query/Item payload, bucket/endpoint, provider credentials, object keys, or internal QA.
- Cesium contract: fetch the bounded manifest, enforce size and strict schema, verify its SHA-256 against `imageryChecksum`, require the same Release/version/bbox/relative template, then create `Cesium.UrlTemplateImageryProvider` with the server-derived release base, `WebMercatorTilingScheme`, 256×256 tiles, levels 0–14, explicit AOI `Rectangle`, `hasAlphaChannel=true`, no pick-feature URL, and the projected credit. Manifest and provider/delivery tests enforce per-tile hashes; do not add a custom imagery framework unless runtime per-request hash verification becomes an explicit acceptance requirement.
- fallback: keep `NEUTRAL_GRID` as a separate labeled reference layer beneath imagery. It is visible whenever no eligible imagery descriptor exists, manifest/provider initialization fails, or the imagery layer is turned off. It is hidden only while the real Release is `READY` and visible. Any imagery request/decode failure marks imagery `FAILED`, restores the grid, and leaves terrain/roads/Places usable. The grid is never described as aerial/satellite imagery.
- attribution/source/freshness projection: the visible Cesium credit and accessible source detail must use the registered/public-safe values: `Contains modified Copernicus Sentinel data [acquisition year]`, AWS access citation/date, Source name, licence link, exact sensing timestamp, coverage/resolution, and `UNKNOWN` verification/accuracy. Do not label acquisition age as “current”.
- exact blockers: active production AOI geometry/version not read in this run; acquisition window and proposed cloud/SCL policy not owner-accepted; live candidate Item(s) not selected; exact source CRS/product ID/time/baseline/assets/checksums unknown; valid-pixel containment and one-Item/mosaic requirement unknown; Source rights/public notices not owner-accepted; no source bytes, pipeline, QA, Dataset/Release UUIDs, R2 objects/receipt, publication, public projection, Cesium integration, provider check, or browser observation.
- implementation work required: one bounded imagery source-lock/acquisition command, strict manifest schema, deterministic processor and smallest QA check, imagery-specific APPROVED registrar, narrow `IMAGERY` branches in published-asset resolution/delivery/publication/publicLayers, ViewerConfig additions, native Cesium URL-template integration with neutral fallback, and focused unit/PostGIS/provider/Playwright tests. No schema migration, new provider architecture, or new dependency is expected unless implementation evidence proves otherwise.
