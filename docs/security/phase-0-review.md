# Phase 0 security review

This review covers the independent LAND repository, local production runtime, PostGIS integration and browser workflows. It is not a penetration-test certification or a claim about an unconfigured public deployment.

Production `pnpm --filter @land/web start` validates environment syntax, HTTPS (or loopback for QA), LAND product identity, nonprivileged database role and access to the private import/parser volume before starting Next. The direct framework CLI bypasses this wrapper and is not the supported deployment entry point. Missing/invalid configuration fails with safe messages. Root builds additionally remove Cesium's shipped demonstration token before minification; no provider token is needed for this local release workflow.

Boundaries verified in automated tests:

- Admin sessions are opaque, hashed in PostgreSQL, HttpOnly/SameSite=Strict/Secure in production; disabled accounts and changed roles are checked again on every request. Cookie-authenticated writes require the configured Origin. Separate read/edit/import/verify/publish/configure permissions guard mutations.
- `land_app` cannot change credential tables, erase audit, edit AOI, create databases/roles or act as superuser. Migration/bootstrap operations are dedicated LAND owner commands. No BIKER/TRIP database, account or provider credentials are used.
- Public DTOs are explicit projections. Drafts, archives, review-required places, unavailable sources, missing rights and disabled/kill-switched providers are excluded. Geometry/content provenance and independent UNKNOWN states survive edit/import. Private notes, raw rows, internal actor/source-record IDs and provider payloads are excluded.
- XLSX is bounded by actual streamed/decompressed sizes and type/container checks; formulas/macros and account sheets cannot become runtime configuration. Parsing occurs in a bounded child with no application secrets, restricted filesystem/process permissions and no write access. Production needs OS/container isolation as well. Commit rechecks current source/geometry/category/duplicate state and rolls back all rows/audit/provenance on any error.
- Geometry, committed import provenance, source observations and published release bytes/metadata are protected from destructive rewrite. Version conflicts prevent silent overwrite. Verification requires explicit evidence/method/authorized actor; import never verifies.
- HTML text is rendered by React; URL input accepts HTTPS without user/password. Server code does not fetch media URLs to bypass browser restrictions. Response headers deny framing, disable camera/microphone/geolocation and prevent MIME sniffing. Spatial assets alone have immutable public caching; API responses are no-store.
- Terrain manifests and tiles have size, checksum, CRS, finite-value and LOD checks. Missing WebGL, invalid terrain and failed lazy engine download leave usable search/details. The upstream Cesium demo credential is stripped at build time and token assignment is empty at runtime.

`pnpm check` includes secret scanning of tracked/new nonignored repository files and emitted public static/Cesium assets, including comparison against local environment/QA secrets without printing values. It checks high-confidence key/JWT/private-key patterns; it is defense in depth, not proof against every encoded/novel secret. Build parses every emitted client chunk, catching the observed minifier regression. `pnpm audit --prod --audit-level high` checks known production dependency advisories. Keep reports containing cookies/form state private; ignored test traces are not release artifacts.

Production prerequisites remain operator responsibilities: HTTPS, trusted ingress rate limits and body/time limits, a private durable import volume with cleanup, separate least-privileged runtime credentials, managed logs/backups, outbound/OS isolation for parsing, source licence review and immutable object-store/CDN policy. A source kill switch prevents new API projections; revoke already published CDN assets with the storage provider as well when required. Do not interpret UNKNOWN legal, field accuracy, road access or safety as approved facts.
