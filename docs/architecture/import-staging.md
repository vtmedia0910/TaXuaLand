# Workbook inspection and staging

POST `/api/admin/imports?sourceId=<uuid>` accepts the raw XLSX body, exact XLSX MIME and a percent-encoded `X-File-Name` header. Session, import permission and same-origin checks run before reading its bounded stream. XLSM and misleading extensions are rejected. Upload limit is 8 MiB; per-actor limit is 20 accepted workbooks/hour.

The child parser gets no database/provider credentials. Node permission flags limit filesystem reads to parser modules/dependencies and deny writes/process spawning. Heap is capped at 192 MiB, processing at 20 seconds and active parsers at two per application process. Run the production service in its isolated container/service account; Node permissions are defense in depth, not a substitute for OS isolation.

Yauzl decompresses sequentially and checks actual entry sizes before ExcelJS parsing. Limits: 32 MiB expanded, 16 MiB/entry, 1,000 entries, 20 sheets, 2,000 rows/sheet, 80 columns, 10,000 characters/cell and 8 MiB normalized text. Duplicate archive paths, encrypted entries, VBA/macros, embedded objects and XML DTD/entities are rejected. Formulas are neither evaluated nor accepted as imported values.

Hidden/account/credential sheets are excluded before storing any of their cells or headers. Obvious credential values in eligible cells are redacted and make mapped rows invalid. Original workbook bytes are SHA-256 hashed and discarded; only sanitized eligible cells remain in private `work/imports/<uuid>.json`. Neither the inspection file nor its storage path has a public route. This intentional policy avoids retaining accidental account-sheet secrets. Run `infra/expire-import-files.mjs` daily with the dedicated LAND maintenance connection to remove expired inspection files after seven days; immutable provenance hashes, row review history and audit remain in PostGIS. API access to expired inspection files is blocked even before cleanup runs.

Mapping is deterministic and explicit. The source registry selection is authoritative; workbook source labels remain labels. Dates require ISO UTC or YYYY-MM-DD. Latitude/longitude strings retain decimal precision; reverse and Google URL coordinates are comparison candidates only. PostgreSQL validates the active AOI and uses geography metres for duplicate proximity and mapped road context. Missing/unknown categories generate warnings, never invented categories. Staging is transactional, bounded to 60 seconds, and cannot be rerun over reviewed rows. A new upload is required to change mapping. No place/source-record publication occurs during staging.

Dependency rationale: ExcelJS 4.4.0 reads cell types without executing formulas; yauzl 3.4.0 performs explicit ZIP validation. ExcelJS's `uuid` is overridden to CommonJS-compatible 11.1.1 to address [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq). Parser behavior is tested with synthetic XLSX containers, including formulas, account sheets, malformed ZIP, macro and expanded-size cases.

Production deployment must include the monorepo parser sources/dependencies and a durable private volume for `work/imports`; set `LAND_WORKSPACE_ROOT` to that monorepo root. Ephemeral serverless filesystem deployment is not supported by this local worker adapter.

Review keeps immutable before/after history and the original sanitized row/hash. Corrections return to REVIEW_LATER: newly computed warnings must be read before approval. Revalidation refreshes current spatial/duplicate context and likewise resets the decision. UPDATE explicitly confirms full replacement of the target content and position; it records the target version and preserves previous content/geometry history.

Commit requires every row to have an explicit CREATE, UPDATE or SKIP decision. INVALID rows can only be skipped. Batch version, target version, source availability, current AOI, category availability and newly introduced duplicate candidates are rechecked in the transaction. Import commits serialize using a transaction advisory lock; target rows lock in UUID order. A narrow security-definer function locks the active AOI without granting runtime any AOI write permission. Lock wait is bounded to five seconds, each statement to fifteen seconds and row processing to sixty seconds. Late errors roll back places, source records and audit together.

The batch ID is the idempotency boundary. A concurrent/repeated confirmed commit returns its stored result without repeating mutations. Each imported source record links uniquely to its staged row, batch, observed date and original row hash. CREATE and UPDATE produce DRAFT places; a new UNKNOWN geometry observation is appended even if imported coordinates equal the old coordinates. Access/safety observations also start UNKNOWN. Publication remains a separate review. Committed rows/results and source provenance are protected by database triggers; expired inspection-file cleanup can still clear the storage pointer.
